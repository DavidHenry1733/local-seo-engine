one small structural improvement now:

Use scene names that match your page intent long term.

Instead of:

hero
trust
conversion

I’d keep:

hero
support
conversion

Why:

trust works well for web design pages
but for Local SEO pages the middle scene may later be:
rankings
visibility
GBP
map pack
support is more flexible as the generic slot name, while the prompt/composition can still be trust-based for web design pages

So:

asset slot = support
scene composition = handshake / credibility / proof for web design pages

That avoids repainting the architecture later.

On the timeout workaround

The addScene.ts one-scene-per-run approach is sensible.
Given the time limit, I’d use it.

That said, make sure image-assets.json is keyed by both:

slug
scene

Not just scene globally.

You want storage shaped like this conceptually:

{
  "web-design-fulwood": {
    "hero": {...},
    "support": {...},
    "conversion": {...}
  }
}

not:

{
  "hero": {...},
  "support": {...},
  "conversion": {...}
}

Otherwise one page can overwrite another.
